# Конвенції написання тестів

Повний перелік конвенцій TAF: і ті, що вже діють, і ціль. У кожного правила статус:

- **[діє: механізм, ПР, дата]** — правило вже перевіряється в репо TAF (гейт `debt:check`, lint, typecheck, git-хук) або закріплене документом репо. Текст для автора тесту ("що писати натомість") живе в `docs/test-conventions.md` репо TAF, посилання `→ #якір` веде на запис там.
- **[ціль: задача]** — правило ввімкнеться, коли задачу плану завершено. Від ПР його не вимагаємо (`docs/pull-request-guide.md`, §5.4).

Коли задача вмикає правило, у тому самому ПР зʼявляється запис у `docs/test-conventions.md`, а тут статус змінюється з "ціль" на "діє". Для гейтових патернів це перевіряє `--self-test` у `scripts/debt.js`. Записи в репо не видаляються: `docs/test-conventions.md` — це історія закритого боргу, ця сторінка — шлях до цілі.

## Структура тесту
- Spec-файл не більше 800 рядків (жорстка межа 1 500). Один describe-блок або feature-area на файл. Файл, що росте понад межу, ділиться до додавання нового тесту, а не після. **[ціль: T1-18; `npm run debt` рахує файли > 1 500 рядків, lint `max-lines` нема]**
- Стан, спільний для кількох тестів у файлі (`let` на рівні модуля, `beforeAll`), заборонений: він переїжджає у фікстуру. **[ціль: T1-08]**
- Один тест перевіряє одну поведінку. Якщо в тесті більше 8–10 `expect`, це кілька тестів. **[ціль: ревʼю після T3-09]**
- Кроки лише через `test.step`, 3–5 на тест, на рівні бізнес-дії ("Confirm PO", "Verify status Approved"). Без вкладених кроків. Без кроків усередині page-об'єктів і фікстур. **[ціль: T1-11, ADR-003]**
- Кожен тест має `annotation: { type: 'QaseID', description: '<id>' }`; на `test.describe` анотація заборонена. **[діє: lint `local/require-qase-annotation` з #148, 11.09, у гейті з #203, 05.10 → `#lint-qase-annotation`]**
- Назва тесту описує поведінку; Python-стиль `test_...` заборонено. **[ціль: ревʼю після T3-09]**
- `allure.*` у тестовому коді заборонено. **[ціль: T1-11, ADR-003]**

## Preparation
- Стан створюється фікстурою (`confirmedPo`, `approvedInvoice`) або через `apiClient`. UI для preparation лише якщо для цього нема API, і тоді це TODO з посиланням на ендпоінт у Swagger. **[ціль: T1-08]**
- Логін тільки через фікстуру `asUser(email)`; `doLogin`, `LoginPage`, `logout_url` у тестах заборонено. **[ціль: після міграції; показник `doLogin / new LoginPage in specs` у `debt.js`]**
- Прямі `db.*` виклики у спеках заборонені; читання ID через API або фікстуру. **[ціль: після міграції; показник `db. in specs`]**
- Тест, що змінює company-wide налаштування, повертає їх у фікстурі після `use()` або у `finally`. **[ціль: T1-08]**

## Дані
- Унікальні імена сутностей через `RandomHelpers` з префіксом `at_`, ніяких літеральних імен із дампу (`'Main'`, `'Amazon'`) у нових тестах. Іменовані сутності беруться з реєстру компанії. **[ціль: ADR-007]**
- Створене тестом видаляється тим, хто створив: фікстура після `use()`, тест у `finally`. **[ціль: T1-08]**

## Перевірки
- Перевірка того, що показує сторінка, лише web-first: `await expect(locator).toX()`. Значення, прочитане один раз зі сторінки чи БД, не порівнюється (`expect(await page.getX()).toBe(...)`); асинхронне значення з API чи БД — через `expect.poll`. **[діє: lint `playwright/prefer-web-first-assertions`; гейт `expect over a page or db value`, #206, 05.10 → `#gate-value-assertions`]**

## Дії та очікування
- `waitForTimeout`, `setTimeout`-паузи, ручні polling-цикли і `networkidle` заборонені; замість них auto-wait, web-first `expect`, `expect.poll` / `toPass`. **[діє: lint `playwright/no-wait-for-timeout`; гейт `waitForTimeout` (#203, 05.10), `sleeps`, `loops with a sleep`, `networkidle waits` (#211, 05.10) → `#gate-waits`]**
- Таймаут у коді лише як `Timeouts.slow` для відомо повільної операції; решта бере значення конфігу (`src/config/timeouts.ts`, `TIMEOUT_MULTIPLIER`). Число лишається тільки в очікуванні, результат якого ловиться (відповідь "нема"). **[діє: гейт `timeout literals`, #211, 05.10, ADR-010 → `#gate-timeout-literals`; зниження значень до конвенційних: ціль T1-29]**
- `.catch(() => {})` лише з коментарем-причиною всередині. `waitFor(...).then(() => true).catch(() => false)` дозволено в `is*` / `has*` / `check*` (AUTO-7817). **[діє: гейт `catch(() => {})`, #203, 05.10 → `#gate-empty-catch`; `.catch` поза предикатами → 0: ціль T2-02]**
- `force: true`, `clickUsingJavascript`, `dispatchEvent` лише з коментарем `// force: <причина>` над рядком. **[ціль: T2-01, ADR-006; зараз вимога в `CLAUDE.md` (AUTO-7817) без перевірки]**
- `.first()` / `.nth()` / `.last()` лише з коментарем, чому локатор не може бути строгим. **[ціль: `metrics.md`, "≤ 100, кожен свідомий"]**
- Усі async-виклики з `await`. **[діє: lint `@typescript-eslint/no-floating-promises`, у гейті з #203, 05.10 → `#lint-floating-promises`]**

## Локатори
- Порядок пріоритету: `getByTestId` → `getByRole` → `getByLabel/Text` з i18n → CSS. XPath лише якщо інакше неможливо, з коментарем. **[ціль: після T2-09]**
- `data-test-id` це контракт із фронтендом: нема test-id на елементі, спершу запит на test-id у фронтенд, а не локатор по верстці. Зміна або видалення test-id на боці продукту узгоджується з AQA. **[ціль: T2-09]**
- Локатори з параметрами це функції, що повертають `Locator`, з екрануванням. Плейсхолдер `'{}'` заборонено. **[ціль: ADR-004]**
- Текстові локатори англійською заборонені: мова прогону ротується. **[ціль: T0-07]**

## Теги
- Рівно один тег компанії. **[ціль: ревʼю; ADR-011]**
- Один тег рівня: `@gate` (біжить на кожному PR), `@module:<name>`, `@nightly`. **[ціль: після tiering; ADR-011 (proposed) пропонує брати склад прогону з Qase, а не з тегів у коді]**
- `@quarantine` з датою і посиланням на задачу; без дати тег не мержиться. **[ціль: T1-20; ADR-011 (proposed) може перенести стан тесту в Qase]**

## Спільні UI-елементи
- Popup, банери, тости, cookie-плашки обробляються в одному місці (BasePage), тести про них не знають. **[ціль: T1-21]**
- PR у продукті, що змінює спільний компонент, позначає AQA до мержу. Правило процесу, узгоджується з розробкою. **[ціль: T2-09]**

## Візуальні перевірки
- Тест із піксельним порівнянням (`toHaveScreenshot`, `toMatchSnapshot`) живе лише в проекті `visual` із тегом `@visual`: поза gate, поза smoke + модуль, поза flaky-метрикою. **[ціль: T2-06]**
- Еталони оновлюються окремим кроком після редизайну, не разом із фіксом тесту. **[ціль: T2-06]**

## Карантин
- Тест вимикається лише тегом `@quarantine` з власником, датою і посиланням на задачу. Вимкнення в Qase без карантину заборонено. Прострочений карантин робить CI червоним. **[ціль: T1-20]**

## PR у TAF
- `typecheck` і `lint` зелені. **[діє: гейт `checks`, #203, 05.10 → `#lint-typecheck`]**
- У кожному зміненому файлі гейтових патернів не більше, ніж у `develop`. Загальна цифра і негейтові показники можуть рости разом із новими тестами, це не ріст боргу. **[діє: гейт `debt:check`, #203, 05.10 (T0-13) → `#debt-check-report`]**
- Коміт проходить Prettier і eslint (`pre-commit`), пуш — typecheck, lint, `debt:check` (`pre-push`); `--no-verify` заборонено. **[діє: husky, #203, 05.10 (T0-28) → `#hooks`]**
- Опис за `docs/pull-request-guide.md`: заголовок англійською, опис українською, результат прогону цифрами. **[діє: гайд, #212, 06.10; перевіряє ревʼю]**
- ПР, що вмикає гейтовий патерн або lint-правило, додає запис у `docs/test-conventions.md` і міняє статус правила тут. **[ціль: T3-09, ПР у роботі; після мержу діє через `--self-test` у `debt.js` для гейтових патернів]**
