# Конвенції написання тестів

Правила для будь-кого, хто додає або змінює тест. Кожне правило має або lint-перевірку, або пункт у ревʼю. Правила з позначкою **[після міграції]** вмикаються, коли відповідний крок роадмапу завершено.

## Структура тесту
- Один тест перевіряє одну поведінку. Якщо в тесті більше 8–10 `expect`, це кілька тестів.
- Кроки лише через `test.step`, 3–5 на тест, на рівні бізнес-дії ("Confirm PO", "Verify status Approved"). Без вкладених кроків. Без кроків усередині page-об'єктів і фікстур.
- Назва тесту описує поведінку і містить Qase-ID: `'PO cannot be confirmed without supplier @qase(1234)'`. Python-стиль `test_...` заборонено.
- `allure.*` у тестовому коді заборонено. **[після міграції]**

## Preparation
- Стан створюється фікстурою (`confirmedPo`, `approvedInvoice`) або через `apiClient`. UI для preparation лише якщо для цього нема API, і тоді це TODO з посиланням на ендпоінт у Swagger.
- Логін тільки через фікстуру `asUser(email)`; `doLogin`, `LoginPage`, `logout_url` у тестах заборонено. **[після міграції]**
- Прямі `db.*` виклики у спеках заборонені; читання ID через API або фікстуру. **[після міграції]**
- Тест, що змінює company-wide налаштування, або повертає їх у `finally`/фікстурі, або живе в проекті, позначеному `@mutates_settings`.

## Дані
- Унікальні імена сутностей через `RandomHelpers` з префіксом `at_`, ніяких літеральних імен із дампу (`'Main'`, `'Amazon'`) у нових тестах. Іменовані сутності беруться з реєстру компанії.
- Створене тестом видаляється тим, хто створив: фікстура після `use()`, тест у `finally`.

## Перевірки
- Тільки `await expect(locator).toX()`. `expect(await x.isVisible()).toBe(true)` заборонено (lint).
- Значення з API або DB порівнюються через `expect.poll` там, де є асинхронність.

## Дії та очікування
- `waitForTimeout`, `sleep`, ручні polling-цикли заборонені (lint). Замість них `expect.poll` / `toPass`.
- `force: true`, `clickUsingJavascript`, `dispatchEvent` лише з коментарем `// force: <причина>` над рядком.
- `.first()` лише з коментарем, чому локатор не може бути строгим.

## Локатори
- Порядок пріоритету: `getByTestId` → `getByRole` → `getByLabel/Text` з i18n → CSS. XPath лише якщо інакше неможливо, з коментарем.
- Локатори з параметрами це функції, що повертають `Locator`, з екрануванням. Плейсхолдер `'{}'` заборонено.
- Текстові локатори англійською заборонені: мова прогону ротується.

## Теги
- Рівно один тег компанії.
- Один тег рівня: `@gate` (біжить на кожному PR), `@module:<name>`, `@nightly`. **[після tiering]**
- `@quarantine` з датою і посиланням на задачу; без дати тег не мержиться.

## PR у TAF
- `tsc` і `eslint` зелені.
- Лічильники контрольного лічильника не зросли.
- Новий тест прогнано локально і на Precorino, посилання на прогін у PR.
