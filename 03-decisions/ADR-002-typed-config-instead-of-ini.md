# ADR-002: Типізований конфіг замість INI
Статус: Draft
Дата: 2026-09-16

## Контекст
INI — артефакт Python `configparser`: один файл `configuration.ini` на 213 ключів (на момент ADR копій було сім по ~220 ключів; звели до однієї раніше), секрети всередині, `Constants` у 2 140 місцях. З 339 ключів, які код реально читає, на середовище залежать 14, і майже всі з них це шлях проти хоста; решта — юзери (124) і константи коду (201), помилково винесені в конфіг. Невідомий ключ компілятор уже ловить, але ціною блоку explicit properties на 376 рядків у `read_configs.ts`, який треба правити руками; дірка протилежна — ключ, оголошений у цьому блоці без джерела в INI, має тип `string` і значення `undefined` (`custom_numbering_main_user`). Єдині споживачі INI: `run_env.ts`, `read_configs.ts`. Цифри: `01-context/audit/config-keys-2026-10-06.md` (T0-11, 2026-10-06), раніші `01-context/taf-as-is.md`.

## Рішення
Типізований конфіг у коді з override на середовище лише з відмінностями, секрети через env із валідацією на старті. Шляхи сторінок і шаблони URL переїжджають у page-об'єкти, юзери в реєстр компаній. INI видаляються повністю. Форма: `04-target/config.md`.

## Наслідки
- Відсутній ключ ловить компілятор; дрейф неможливий за побудовою.
- `read_configs.ts` 671 рядків (609 на момент ADR) → ~50; блок explicit properties на 376 ключів зникає разом з INI.
- Прод-профіль потребує окремого рішення (питання #8).

## Міграція
Strangler: `Constants` як фасад над новим конфігом, codemod call-site, видалення фасаду. Задачі T0-11, T1-01, T1-02.

## Відхилені альтернативи
- Лишити INI, дописати типи: не прибирає сім копій і дрейф.
- YAML/JSON: та сама проблема без типів і override.
