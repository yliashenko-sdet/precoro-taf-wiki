# ADR-005: API-клієнт генерується зі Swagger
Статус: Draft (proposed)
Дата: 2026-09-16

## Контекст
241 ручний метод, non-2xx не кидає, 7 типів на весь API, ~177 із 507 Swagger-ендпоінтів покрито; не покриті саме lifecycle-переходи, через що "документ у статусі X" будується через UI. Swagger покриває публічний API до Locations; users, roles, settings, custom forms ідуть внутрішніми ендпоінтами. Цифри: `01-context/taf-as-is.md`, перелік: `01-context/swagger-endpoints.txt`.

## Рішення
Типи і клієнт генеруються зі Swagger; non-2xx кидає за замовчуванням; два клієнти з явними назвами `publicApi` та `internalApi`; обгортка з атачами як middleware; ajv зі схемами з OpenAPI; contract-check у CI. Форма: `04-target/api-client.md`.

## Наслідки
- Розрив між API і клієнтом не повертається.
- 219 `expect(statusCode)` у фікстурах зникають.
- Різна стабільність public/internal стає видимою в коді.

## Міграція
Новий клієнт поруч зі старим, фікстури переїжджають першими, старий видаляється при нулі імпортів. Швидка перемога до генерації: задача T1-07. Повна генерація: фаза 3.

## Якість специфікації: виміряно 2026-09-22
Файл: `01-context/archive/precoro-openapi-2026-09-22.json` (1.3 МБ).

| Показник | Значення |
|---|---|
| Версія | OpenAPI 3.0.0, валідна структура |
| Шляхів / операцій | 447 / 521 (більше за текстовий перелік на 507: специфікація росте) |
| З `operationId` | 521 із 521, усі унікальні |
| Зі схемою відповіді 2xx | 329 із 521 (63%), з них 308 через `$ref` |
| Схем у `components` | 115, з них 61 із `required`, 1 936 властивостей |
| Не-GET операцій із `requestBody` | 125 із 339 |

**Головне число:** клієнт TAF будує 172 унікальні шляхи; 121 із них є у специфікації, 104 мають схему відповіді. Тобто 60% усіх викликів фреймворку валідуються одразу, без домовленостей з розробкою. Зараз валідується нуль.

**Поділ public/internal підтверджено цифрами:** 121 шлях публічний, 51 поза специфікацією (`/api/ap/documents`, `/api/companies/current`, `/api/categories`, `/api/attachments/...`), це внутрішній API, знятий із фронту.

**Що просити в розробки:** 192 операції без схеми відповіді загалом, але з тих, які TAF викликає, таких лише 17. Це конкретний короткий список, а не прохання переписати документацію.

## Вибір генератора: вирішено 2026-09-22
`operationId` є скрізь, тому `swagger-typescript-api` технічно підходить, але імена в специфікації виду `get_api_get_document_custom_fields` дадуть методи `getApiGetDocumentCustomFields` замість нинішніх `getDcfList`.

Рішення: `openapi-typescript` для типів і схем, а наявні іменовані методи `precoro_service.ts` лишаються **тонким фасадом** над згенерованим клієнтом. Тоді 101 місце виклику в тестах не змінюється, а типи і валідація з'являються. Фасад поступово худне до делегування.

## Типи це не валідація
Згенеровані типи діють лише на компіляції. Сенсор із T1-24 потребує рантайм-схем із тієї ж специфікації: `ajv` зі схемами з `components/schemas` або згенеровані zod-схеми (кращі повідомлення про помилку). Генерація одна, артефакти два.

## Джерело OpenAPI
`GET app.precorino.com/api/docs` повертає повний JSON; у CI генерація тягне його звідти (питання #6 закрито 2026-09-16).

## Відкрито Уточнено 2026-09-16: Swagger ще в розробці, нові ендпоінти очікуються 18.09; OCR ходить внутрішніми запитами, знятими з фронту, тобто поділ `publicApi`/`internalApi` підтверджений і `internalApi` лишається надовго. Перелік у `01-context/swagger-endpoints.txt` оновити після 18.09.
