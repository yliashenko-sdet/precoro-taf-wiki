# ADR-005: API-клієнт генерується зі Swagger
Статус: Draft (proposed)
Дата: 2026-09-16

## Контекст
241 ручний метод, non-2xx не кидає, 7 типів на весь API, ~177 із 507 Swagger-ендпоінтів покрито; не покриті саме lifecycle-переходи, через що "документ у статусі X" будується через UI. Swagger покриває публічний API до Locations; users, roles, settings, custom forms ідуть внутрішніми ендпоінтами. Цифри: `01-context/taf-as-is.md`, перелік: `01-context/swagger-endpoints.txt`.

## Рішення
Типи і клієнт генеруються зі Swagger; non-2xx кидає за замовчуванням; два клієнти з явними назвами `publicApi` та `internalApi`; обгортка з атачами як middleware; ajv зі схемами з OpenAPI; contract-check у CI. Форма: `04-target/api-client.md`.

## Наслідки
- Розрив між API і клієнтом не повертається.
- 219 `expect(statusCode)` у фікстурах зникають.
- Різна стабільність public/internal стає видимою в коді.

## Міграція
Новий клієнт поруч зі старим, фікстури переїжджають першими, старий видаляється при нулі імпортів. Швидка перемога до генерації: задача T1-07. Повна генерація: фаза 3.

## Передумова: якість специфікації
Перед вибором генератора перевірити на збереженому JSON із `/api/docs`:
1. Документ валідний за OpenAPI.
2. Частка операцій із `operationId` (визначає, чи будуть нормальні імена методів).
3. Частка операцій з описаною схемою відповіді 200, а не лише кодом (без цього сенсору з T1-24 нема з чим звіряти).
4. Частка схем із `required` (без нього валідація знову стане поверхневою, як зараз).
Якщо відповіді не описані, першим кроком стає домовленість з розробкою, а не генерація.

## Вибір генератора
- `swagger-typescript-api`: клієнт з іменованими методами, найближче до нинішнього `precoro_service.ts` (`precoro_api.createContract(...)`), мінімум правок у викликах. Залежить від якості `operationId`.
- `openapi-typescript` + `openapi-fetch`: лише типи плюс тонкий клієнт, виклик шляхом (`api.POST('/purchaseorders/{idn}/confirm', ...)`). Імена не потрібні, типізація строга, стиль викликів інший.
Вибір після пункту 2 передумови.

## Типи це не валідація
Згенеровані типи діють лише на компіляції. Сенсор із T1-24 потребує рантайм-схем із тієї ж специфікації: `ajv` зі схемами з `components/schemas` або згенеровані zod-схеми (кращі повідомлення про помилку). Генерація одна, артефакти два.

## Джерело OpenAPI
`GET app.precorino.com/api/docs` повертає повний JSON; у CI генерація тягне його звідти (питання #6 закрито 2026-09-16).
