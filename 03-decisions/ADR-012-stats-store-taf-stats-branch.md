# ADR-012: Статистика прогонів живе в гілці `taf-stats` репозиторію TAF у фіксованому форматі
Статус: Draft (proposed)
Дата: 2026-10-26

## Контекст
Щоденний збір (`team_stats.py`, launchd о 12:00) працює на ноутбуці Євгена, а сховище (`~/Work/Precoro/stats`) локальний git без remote. Залежність від одного Mac: вимкнений ноутбук пропускає збір, Jenkins зберігає лише 31 нічну збірку, гілки зникають разом з історією.

Джерела прогонів множаться:
- нічний прогін у QA Jenkins (унікальне середовище з мікросервісами; джерело — Allure);
- гілкові прогони тепер у GitHub Actions продукту (`precoro/precoro`, workflow `PR Checks`); Allure там не вивантажується, джерело — лог Playwright (списки `failed` і `flaky`, помилка кожної спроби, `Slow test file`); dev Jenkins з 21.10 порожній;
- новий екшн «фіксова гілка → develop» з фулраном у TAF (будується окремо), теж має писати статистику.

Перевірено 26.10 на 92 логах Playwright-джобів продукту (22–26.10, 84 запуски, 56 гілок): лог містить проєкт, файл:рядок, назву, помилку кожної невдалої спроби для `failed` і `flaky`; кількість блоків помилок (230) дорівнює сумі `failed` (117) і `flaky` (113). Артефакт `playwright-report-*` живе 2 дні і лише при падінні; трейс знімається лише на останній спробі.

## Рішення
1. **Сховище** — окрема гілка `taf-stats` у репозиторії TAF без спільної історії з кодом (orphan). Дані туди пушаться напряму, без PR і без рев'ю; код збирача і workflow живуть у `develop` звичайним шляхом.
2. **Один файл на запуск, незмінний**: `data/<source>/<рік>/<id>.json`. Паралельні записи не конфліктують, повторний запис ідемпотентний (існуючий файл пропускається).
3. **Формат — контракт**: `schema/v1.json` (JSON Schema) у цій же гілці. Усе, що потрапляє в `data/`, проходить валідацію.
4. **Єдина точка запису** — скрипт `scripts/stats/write-run` у TAF: приймає запис, перевіряє проти схеми, робить checkout `taf-stats`, коміт, `pull --rebase`, `push` із повтором, під `concurrency`-групою. Пряме редагування `data/` вручну чи іншим кодом не передбачене.
5. **Дві форми надходження**: pull (збирач за розкладом забирає нічний із Jenkins і гілкові з логів GHA продукту токеном лише на читання) і push (екшн у TAF викликає `write-run` після свого прогону). Нове джерело = нова тека в `data/` і значення `source`.
6. **Споживачі** читають лише `taf-stats`: тижневий звіт (weekly), дані сторінки-артефакта, екшн ранкового розбору (T0-30).
7. Сирі логи і трейси не зберігаються: лише розібраний запис (розмір і дані середовища).

### Формат запису v1 (чернетка)
```
{
  "schema": 1,
  "source": "nightly | branch | fix-to-develop | ...",
  "run": { "id", "url", "started_at", "duration_s", "branch", "sha", "suite", "conclusion", "env" },
  "totals": { "executed", "passed", "failed", "flaky", "skipped", "did_not_run", "machine_ms"? },
  "slow_files": [ { "project", "file", "duration_s" } ],
  "tests": [ { "project", "file", "line"?, "title", "qase_ids"?, "status": "failed | flaky",
               "retries", "error_class", "error" (до 300 символів) } ]
}
```
Лише `failed` і `flaky` потрапляють у `tests`; пройдені лічаться в `totals`. Поля з `?` необов'язкові (нічний Allure не дає рядка). `error_class` — симптом (таймаут локатора, assertion, таймаут тесту, помилка API, помилка скрипта, інше), не причина.

## Наслідки
- Збір не залежить від ноутбука; історія нічних більше не обмежена 31 збіркою.
- Нове джерело додається без зміни споживачів, якщо пише за схемою.
- Код збирача переписується з Python на Node (`scripts/*.js` у репо TAF, runner має Node); `team_stats.py` лишається тимчасово, поки не перенесено показники.
- Гірше: потрібні права `contents: write` у workflow, виключення `taf-stats` з правил захисту гілок (адмін репо) і токен лише на читання Actions у `precoro/precoro`.
- Гірше: досяжність QA Jenkins із раннера GitHub не перевірена; якщо ні, нічний сам викликає `write-run` у кінці прогону (push) або потрібен self-hosted раннер.
- Різні середовища (нічний QA Jenkins і гілкові GHA) зберігаються разом, але в звітах лишаються окремими розділами за `source` (рішення 20.10: числа між ними не порівнюємо).

## Відхилено
- Окремий репозиторій для статистики: не погоджено.
- Коміти зі статистикою в `develop`: шум у журналі PR, `develop` захищений гейтом.
- Лише артефакти запусків: живуть 2 дні.
