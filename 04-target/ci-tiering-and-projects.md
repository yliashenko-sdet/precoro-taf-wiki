# CI, проекти, tiering

ADR-006 для ретраїв; решта ще без ADR. Власник інфраструктури інфра-AQA, TAF задає контракт. Задачі T0-04, T0-06, T0-08, T1-14, T1-15, T1-16.

## Проекти
- Проект = компанія (або підмножина компанії з окремим юзером) і має бути не довшим за 45 хв machine-time, щоб воркери масштабувались до 20+.
- Ділити першими: minor, common, invoice, items, budgets (кожен ~2 год). main_company лише після 11+ воркерів.
- Мертві проекти видаляються; globalSetup логінить лише проекти з тестами.
- `fullyParallel: false` лишається, поки тести не незалежні; ціль увімкнути після реєстру компаній і teardown.

## Tiering
| Тег | Коли біжить | Ціль часу | Політика |
|---|---|---|---|
| `@gate` | кожен PR | ≤ 15 хв | 0 червоних; flaky видимий |
| `@module:<name>` | PR, що торкається модуля | ≤ 30 хв | те саме |
| `@nightly` | ніч, повний | ≤ 60 хв на поточному залізі | тренд |
| `@quarantine` | біжить, не блокує | | дедлайн 2 тижні |

Smoke перебалансовується: зараз 86% у main_company.

## Репортери і артефакти
`html` + `json` + `allure-playwright` (поки читають) + `junit` для Jenkins. Трейс на першому ретраї. Мова і дата прогону в назві білда. JSON у дашборд: machine-time як головний KPI, top-50 за тривалістю, частка preparation зі степів.

## Джоба для девелопера
Параметри: гілка, рівень (`gate`/`module`/`full`), `--last-failed` для перезапуску. Перезапуск повного прогону через одне падіння прибирається.

## Ефемерні середовища
Снапшот з архетипами компаній на старті; дозволяють деструктивні тести без teardown і масштабування воркерів без спільного середовища. Спільна точка з інфра-AQA: версія снапшоту S ↔ версія тестів T.
