# Baseline: що виміряти до початку модифікації

Принцип: метрика існує, лише якщо від неї залежить рішення. Нижче кожна цифра підписана рішенням, яке вона підтримує, і джерелом. Baseline фіксується як названа точка (коміт + номер білда) у `metrics.md`, усі подальші порівняння лише з нею.

Важливо: історія вже накопичена. `metrics-reporter` пише `latest.json` і `history.jsonl` кожного прогону, дашборд показує 15 білдів. Двох тижнів очікування не потрібно; потрібен доступ до наявних артефактів.

## Рівень 1. Доступно сьогодні з коду (хвилини, нікого не треба)

| Метрика | Яке рішення підтримує | Джерело |
| --- | --- | --- |
| Контрольні показники (~15 патернів) | Порядок codemod-ів; доказ щотижневого прогресу | `scripts/debt-counters.ts` (T0-13) |
| Помилки `tsc` / `eslint` | Чи можна вмикати гейт сьогодні | `npm run typecheck`, `lint` |
| Тестів на проект і на файл, розподіл тегів | Що ділити першим (T1-14), tiering (T1-15) | `playwright test --list` |
| Профіль preparation на файл: UI-створення, UI-confirm, UI-логін проти API-створень | Де API-preparation дасть найбільше; черга T1-09..T1-17 | grep по спеках |
| Покриття Swagger клієнтом | Обсяг T1-07 і генерації | `/api/docs` проти `precoro_service.ts` |
| Колізії юзерів і проектів, спеки, що пишуть у чужу компанію | Ризики паралелізму, розбиття проектів | статичний аналіз |
| З'єднання до MySQL, які TAF відкриває в піку | Чи TAF співучасник проблеми потужностей (питання #14) | конфіг пулу × кількість воркерів |

## Рівень 2. Доступно сьогодні, треба попросити в інфра-AQA

| Що просити | Що дає | Навіщо |
| --- | --- | --- |
| `metrics/latest.json` і `history.jsonl` за останні ~15 білдів (отримано лише один прогін, 16.09; історія ще потрібна) | machine-time і flaky по проектах у динаміці, список flaky-тестів кожного білда | Baseline швидкості й стабільності без очікування; «повторні порушники» серед flaky = ті, що падали в ≥2 білдах |
| Архів `allure-results` одного нічного прогону | Тривалість кожного тесту, кроки з таймінгами | Отримано 2026-09-17 (прогін 16.09): результати в `01-context/nightly-run-2026-09-16.md` |
| Конфіг нічної джоби (Jenkinsfile) | Що саме виключено і як | Відтворюваність складу прогону; питання #3 закрите фактом, не словами |
| Доступ до Grafana Precorino: php-fpm воркери, OOM-kill, 5xx, MySQL за нічне вікно | Накласти на таймлайн нічного прогону: які падіння збігаються з піками сервера | Категорії падінь "середовище" замість здогадок; аргумент для Дмитра Ясмо |

## Рівень 3. Один патч і один нічний прогін

| Метрика | Рішення | Задача |
| --- | --- | --- |
| Запити на тест: браузер і API окремо | Доказ ефекту API-preparation, не залежний від завантаження середовища; розрахунок для капасіті | T0-15 |
| `perFile`, `perTag` у репортері | Приймання задач по файлах і тегах | T0-04 |
| Мова прогону в метриках | Відтворюваність падінь | T0-07 |

## Рівень 4. Потребує часу (але baseline уже є)

Тренди flaky і machine-time після змін. Порівнюються з наявними 15 білдами, а не з нуля.

## Мінімальний набір, щоб почати

1. Показники боргу (рівень 1) — сьогодні.
2. machine-time і flaky по проектах з наявної історії (рівень 2, один запит) — сьогодні.
3. Top-50 за тривалістю і частка preparation з одного архіву allure (рівень 2) — сьогодні.
4. Запити на тест (рівень 3) — після першого нічного прогону з патчем.

Пункти 1–3 не блокують нічого: T0-01, T0-02, T0-13 можна робити паралельно.

## Правила порівняння

- Тривалість на спільному Precorino шумна: брати медіану 2–3 нічних прогонів, не один.
- Кількість запитів на тест стабільна: використовувати її як основний приймальний критерій задач API-preparation, тривалість як вторинний.
- Порівнювати лише однакові множини: після відповіді на питання #3 зафіксувати, які проекти і теги входять у нічний прогін.
- Кожна цифра baseline підписана комітом, номером білда, агентом, середовищем і мовою.

## Чого свідомо не міряємо

Покриття продукту тестами у відсотках, кількість рядків коду, кількість assertion, кількість тест-кейсів у Qase. Жодна з цих цифр не змінює рішення в цьому плані і створює хибне відчуття прогресу.
