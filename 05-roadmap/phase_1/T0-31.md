## Три частини: ядро і два види використання
Статистика це ядро, усе інше її споживачі. Окремі гілки й PR від `develop`: спершу ядро, потім споживачі (вони між собою незалежні).

| Частина | Що | Задача |
|---|---|---|
| **1. Ядро** | Збір і сховище: гілка `taf-stats`, `schema/v1.json`, `scripts/stats/write-run`, README читання, парсер Allure нічного і `failure_class`, `stats-collect.yml`, крок запису в `full-run.yml`, перенесення історії зі `stats/raw`, секрети Jenkins, `contents: write` | цей файл (T0-31) |
| **2а. Використання: розбір прогонів** | Нічний розбір (Precorino triage): групування, кластеризація за часом, трейси, розбір Claude, навчальний блок, Check Run, історія флейків групи. Статистика прогонів GHA сюди не входить (рішення Євгена 2026-11-01) | T0-30 |
| **2б. Використання: звіти й метрики** | Тижневий звіт по метриках прогонів і показниках техборгу (`metrics/weekly/*.md`), поверх `taf-stats`, `metrics/history.jsonl` і `npm run debt`; заміна `team_stats.py` і launchd | T0-14 |

Шов між ядром і споживачами один: формат запису v1 (разом із `started_at`, `duration_ms`, `ref`). Споживач лише читає записи за схемою; у джерела (Jenkins) ходить тільки по те, чого сховище не зберігає (повна помилка, кроки, трейс). Розбір (2а) можна починати, щойно схема й перші записи нічного лежать у `taf-stats`, не чекаючи тижневого звіту. PR ядра торкається лише CI і скриптів, не тестів, тож підтверджений прогін для нього не потрібен (у тілі PR написати чому).
