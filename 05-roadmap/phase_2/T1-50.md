# T1-50. [TAFMOD][Gate] Імена в коді: snake_case → camelCase

Етап 2 (рішення Євгена 2026-11-23). Фаза 1, трек C. Codemod-и. ADR: —. Asana: нема.

## Біль

Імена змінних, методів і полів класів частково лишились у Python-стилі з порту з pytest (`location_id`, `actual_ext_id`, `response_status_code`). У TypeScript прийнято camelCase. Через змішані стилі в одному файлі код важче читати, а при рев'ю щоразу виникає питання, як назвати нове. Правила, яке б це тримало, немає, тож нові snake_case-імена і далі потрапляють у код (видно в рев'ю PR, 2026-11-23).

## Що є зараз (`00f4fb4e`, гілка від `develop` `b84ed973`, 2026-11-23)

Замір: тимчасовий конфіг ESLint з `@typescript-eslint/naming-convention` поверх `eslint.config.js`, `npx eslint src`. Селектори: `variable` (camelCase, UPPER_CASE, PascalCase), `parameter`, `function`, `classMethod` (camelCase), `classProperty` (camelCase, UPPER_CASE). Ключі об'єктів не перевіряються: це поля API і БД, вони мають бути такими, як їх чекає сервер.

- Порушень 880 у 62 файлах: змінні 615, поля класів 179, методи 82, параметри 3, функції 1.
- Зосереджено в кількох файлах: `test_api.spec.ts` 572, `src/api/all_json_data.ts` 63, `payments/test_payment_api.spec.ts` 26, білдери в `utilities/builders` по 13–15.
- Серед полів і методів є не snake_case, а інші випадки: схеми в PascalCase (`UsersListSchema`) і методи з `_` на початку (`_uploadFile`, 82 шт.). Для них рішення окреме (крок 2).
- Назви фікстур уже в camelCase, задача їх не торкається.

## Що зробити

1. **Базова цифра.** Додати `naming-convention` у `eslint.config.js` як `warn` з селекторами вище. Записати кількість з `npm run lint` у картку як базу.
2. **Сухий запуск codemod-а.** Скрипт на TypeScript API групує порушення: чистий snake_case; PascalCase-схеми; `_`-префікс; імена, що збігаються з ключем API/БД через shorthand (`{ location_id }`). Групи з цифрами в картку, рішення по кожній групі приймає Євген до запуску з `--write`.
3. **Перейменування codemod-ом.** Rename через мовний сервіс TypeScript (як F2 у редакторі): змінюються оголошення і всі посилання, shorthand-властивість розгортається в `{ location_id: locationId }`, тож тіло запиту не змінюється. Порціями за файлами, `test_api.spec.ts` окремим PR.
4. **Правило в `error`.** Коли порушень 0 (або залишок з `eslint-disable` і причиною), правило стає `error`; запис у `docs/test-conventions.md`.

## Готово, коли

`naming-convention` стоїть як `error` у `eslint.config.js`, `npm run lint` зелений; зачеплені спеки прогнані до і після без нових падінь (набір від скіла `affected-tests`); typecheck зелений.

## Метрика

Порушень `naming-convention` у `src`: 880 у 62 файлах → 0. Категорія: Maintainability. Вплив на час і стабільність прогону не очікується.

## Ризики і залежності

- Shorthand-властивості: перейменування змінної змінить ключ у тілі запиту, якщо codemod не розгорне shorthand. Перевірка: typecheck плюс прогін API-спеків.
- Конфлікти з відкритими PR у тих самих файлах: `test_api.spec.ts` брати, коли в ньому немає відкритих PR.
- Імена в рядках (`test.step('... location_id ...')`, повідомлення `expect`) rename не змінює. Лишаються як є, якщо це назва поля API.
