# T1-51. [TAFMOD] API рівень: 1.2. Незадане поле не потрапляє в тіло запиту; `null` — лише свідоме очищення

Етап 2 (рішення Євгена 2026-11-24). Фаза 1, трек A. Водопровід фреймворку. ADR: —. Asana: нема.

Чернетка (2026-11-24). Підхід кроками і ризики дописуються перед стартом задачі: до того картка не є definition of ready (`../tasks/README.md`).

## Біль

У методах `PrecoroClient` необов'язкові параметри мають за замовчуванням `null`. Тому `null` означає дві різні речі: «тест це поле не задав» і «очисти це поле». Щоб незадане поле не пішло на сервер як `null`, майже кожен метод перед відправкою фільтрує тіло однаковим рядком `Object.fromEntries(Object.entries(data).filter(([, v]) => v !== null && v !== undefined))`. Фільтр прибирає і свідомий `null`, тож там, де поле треба очистити, метод обходить його вручну. Помічено на рев'ю #503 (2026-11-24).

## Що є зараз (`precoro_service.ts`, гілка T1-25 `3ad857a6`, 2026-11-23)

- 3 587 рядків; `Object.fromEntries` 53, з них копій фільтра null/undefined 50; параметрів із `= null` за замовчуванням 79.
- Свідомий `null` потрібен: відв'язати кроки апруву (`nextStep` / `previousStep` → `null` перед видаленням кроку), `addScfOption` з `parent: { id: null }`.
- Бекенд (`precoro` `8db51c977f6`, 2026-11-20) приймає тіло через Symfony `$form->submit($data, $clearMissing)`. У 30 місцях контролерів це `submit(…, false)`, як PATCH: відсутнє поле лишає старе значення, `null` очищає. У 26 це `submit(…)`, як PUT: відсутнє поле очищається теж.

## Що зробити

1. «Не задано» — це `undefined`: параметри з `= null` стають необов'язковими (`x?: T`). axios серіалізує тіло через `JSON.stringify`, який поля з `undefined` пропускає, тож у payload їх просто немає.
2. Прибрати всі копії фільтра: тіло йде таким, яким його зібрав метод.
3. `null` лишається тільки там, де поле очищається свідомо, з коментарем у рядку.
4. Виклики у фікстурах, менеджерах, builders і спеках, що передають `null` у значенні «не задано», передають нічого. Виклик, що передає `null`, щоб очистити поле, лишається.
5. PUT-ендпоінти не міняють того, що надсилають: там відсутнє поле сервер очищає, тож «не надіслав» не означає «лишив як є».

## Ризики

- Виклик, що передавав `null` навмисно, перестане очищати поле, якщо його сплутати з «не задано». Тому кожну заміну `null` у викликах перевіряють за змістом, не автозаміною.
- Розбиття `precoro_service.ts` за доменами (T3-06) переносить ті самі методи. Ця задача йде першою: переносити вже очищений код, а не змішувати в одному PR зміну поведінки і переміщення.

## Готово, коли

Копій фільтра 0; жоден `= null` за замовчуванням не означає «не задано»; кожен свідомий `null` у тілі має коментар; статика зелена; прогін за вердиктом `affected-tests` без нових падінь проти `develop`.
