# T0-01. Зелений `tsc --noEmit` і гейт якості
Біль: P12. Статус: на рев'ю, PR #203 (`feature/liashenko/quality-gate`).

## Контекст
Базова гілка `develop`. Замір 2026-09-24 на `origin/develop` (`ad66840`): `npx tsc --noEmit` дає 6 помилок, усі в двох файлах: `import_invoice_page.ts` і `import_pr_page.ts` викликають `waitForCircularToDisappear` і локатор `loader_mask`, яких у базових класах уже нема. Файли не змінювались з 28.07, отже помилки з'явились, коли змінився базовий код, і ніщо цього не зловило. Це прямий аргумент за гейт.

Три помилки, які аудит бачив на `release` (`remove_budget_btn_part`, `successFlashAppeared`, невикористаний `page`), на `develop` уже виправлені. Ранні локальні правки на `main` відкочено 24.09.

## Підхід
1. `npx tsc --noEmit` на гілці задачі від `develop`, список помилок знімається заново.
2. Кожна помилка виправляється в коді, без `// @ts-ignore`: викликати наявний метод або локатор (`waitForLoaderToDisappear` чи його еквівалент), якщо в базовому класі є заміна; якщо заміни нема, повернути метод у базовий клас.
3. Гейт у GitHub Actions: `.github/workflows/quality.yml` на PR і push у `develop`, кроки Node, `npm ci`, `typecheck`. Причина вибору: жоден Jenkins не тригериться змінами в репо TAF, а Actions на репо вже працюють (Copilot review). Межа: лише статичні перевірки, без E2E (ліміт хвилин приватного репо, нема доступу до Precorino, MySQL і seed). `lint` додається в гейт після T0-02, `debt:check` після T0-13. Обов'язковість для мержу вмикає адмін `avramch` (питання #25).

## Path-scope (ADR-008)
Перевірка стосується лише файлів TAF. Workflow запускається завжди і завершується успіхом, якщо в діфі нема файлів TAF. Фільтр `paths:` не підходить: обов'язкова перевірка на PR без змін у TAF лишиться pending. До об'єднання репозиторіїв це не має значення (у TAF комітять лише QA), після об'єднання стає обов'язковим. Об'єднання відкладено 2026-09-25 (ADR-008); path-scope лишається, бо нічого не коштує.
