# T0-13. Показники боргу і гейт "у файлі не більше, ніж у develop"
Asana: [Прибрати хардкодні таймаути в тестах](https://app.asana.com/0/0/1218768360241378), [Прибрати позиційні селектори](https://app.asana.com/0/0/1217787996352229), [Прибрати розгалуження логіки в тестах](https://app.asana.com/0/0/1217788091082407) — звідти три показники, додані 2026-09-24.
Біль: P12; фундамент для всіх codemod-ів. ADR-001. Статус: wip (локально готове, коміт `aed5042e` на `taf/stage-1`).

## Контекст
Замір 2026-09-25 скриптом `06-playbooks/scripts/debt_counters.sh` (одиниця: рядки) на `release` (`a24f017b`) і `develop` + T0-01/02: числа в `metrics.md` не відтворюються навіть на `release` (`Constants.` 2 054 проти 791, `expect(await` 434 проти 511). Частина боргу на `develop` тане без плану (`waitForTimeout` 70 → 0 через lint-правило, `.catch(() => {})` 133 → 99, `xpath=` 1 050 → 965), частина росте разом із новими тестами General QA (`allure.` +906, `db.` у спеках +56, `timeout: N` +20). Загальна цифра тому не показує, куди рухається борг.

## Правило гейта
Для кожного файлу, зміненого в PR: якщо будь-якого патерну з переліку гейта в ньому стало більше, ніж у `develop`, перевірка червона з файлом, патерном і різницею. Файл, якого в `develop` нема, має там 0. Перейменування береться з `git diff` (rename detection), і файл порівнюється зі старим шляхом.

Виправлений файл чистим і лишається, хто б його не виправив. Загальна цифра може рости через нові тести, і це не вважається зростанням боргу.

Перелік гейта: лише патерни, для яких уже є правильний спосіб (`working-agreement.md`, "Перебудова човна на ходу", п. 3–4). На старті `waitForTimeout` і `.catch(() => {})` (AUTO-7817 у `CLAUDE.md` репо). Кожен codemod додає свій патерн, коли з'являється заміна. Коли патерн закрито в усьому репо, його можна замінити lint-правилом.

## Підхід
1. `scripts/debt.js` (Node, як решта `scripts/`): рахує патерни з `metrics.md` у файлі або в репо, одиниця явна (входження, без коментарів). Лише `typescript` з наявних залежностей.
2. `npm run debt`: таблиця "показник, кількість" на поточному коміті. Цифри не зберігаються: "до і після" codemod-у це запуск на двох комітах.
3. `npm run debt:check`: правило гейта для змінених файлів відносно `origin/develop`.
4. Крок `debt:check` у `.github/workflows/quality.yml` (T0-01).

## Готово, коли
Числа `npm run debt` збігаються з `debt_counters.sh` або різниця пояснена; `debt:check` червоний на `waitForTimeout`, доданому в наявний файл і в новий файл; зелений на простому перейменуванні файлу.

## Ризики
Regex-патерн ловить входження в коментарях і рядках; для кожного патерну 3–5 прикладів у самоперевірці скрипта. Розбиття файлу (T1-18) git не бачить як перейменування: на кроці 0 T1-18 перевірити, що патерни з переліку в цих файлах на нулі.
