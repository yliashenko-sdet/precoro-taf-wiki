# T0-13. Контрольні показники, baseline, CI-гейт "тільки вниз"
Біль: P12; фундамент для всіх codemod-ів. ADR-001.

## Контекст
Перелік показників і спосіб підрахунку кожного: `06-playbooks/measurement.md`, труба 1. Baseline-значення: `05-roadmap/metrics.md`. Нічого з цього ще не існує в коді.

## Підхід
1. `scripts/debt-counters.ts` на ts-morph: для кожного показника функція, що повертає `{ total, byFile }`. Regex-показники через `Project.getSourceFiles()` і `getFullText()`, AST-показники (`catch(() => false)` поза `is*/has*/check*`) через обхід `CallExpression`.
2. `npm run debt` друкує таблицю; `npm run debt -- --json` пише `debt.json`.
3. `debt-baseline.json` у корені, перший коміт = поточна правда.
4. `npm run debt:check`: фактичне > baseline → exit 1 з переліком файлів, де додано; фактичне < baseline → exit 1 з текстом "run `npm run debt:update`"; будь-яке число baseline у PR > baseline в `origin/main` → exit 1.
5. Крок у Jenkins після lint. На мержі в main: рядок у `metrics/debt.jsonl` (той самий каталог, куди пише `metrics-reporter`).
6. Перший тиждень гейт у режимі warning, щоб побачити хибні спрацювання, потім error.

## Готово, коли
Baseline у репозиторії дорівнює правді; PR із зайвим `waitForTimeout` червоний; `debt.jsonl` має перший рядок.

## Ризики
Показник на regex ловить рядки в коментарях; для точності кожен показник має тест на 3–5 прикладах. Файли, які кодмодяться паралельно кимось іншим, дадуть конфлікти в baseline: baseline оновлюється лише в PR, що зменшує борг.

Оцінка: 1–2 дні.
