# T0-28. Git-хуки з перевірками гейта
Біль: P12. Статус: wip, окремим комітом у PR #203 (рішення Yevhen 2026-10-02: гігієна і гейти в одному PR). Продовження T0-01, T0-02, T0-13.

## Контекст
Гейт `checks` у GitHub Actions ловить помилки `tsc`, lint і новий техборг лише після пушу, через 1–2 хв на сторінці PR. Хуків у репо нема: `husky` встановлений (`prepare: husky`), `lint-staged` налаштований на Prettier, але жодного файлу в `.husky/` не закомічено, тож не працює нічого.

Хук локальний і обходиться через `--no-verify`: це раннє попередження, захист дає required check `checks`. Хуки спрацьовують для всіх, хто комітить у TAF, зокрема для сесій Claude (`scripts/fix-failing-tests.sh` і робочі сесії), тому в `CLAUDE.md` репо потрібне правило не обходити хуки.

Замір 2026-10-02 на Mac (гілка `feature/liashenko/quality-gate`): `prettier --check` 3 файли 0,7 s; `eslint` 1–3 змінені файли 2,4–2,9 s; `tsc --noEmit` 6 s; `eslint` весь `src` 12 s; `debt:check` 8 s.

## Підхід
1. `.husky/pre-commit`: `npx lint-staged`; у `lint-staged` для `*.ts` додати `eslint` до наявного `prettier --write`. Перевіряє лише файли коміту, кілька секунд.
2. `.husky/pre-push`: `npm run typecheck && npm run lint && npm run debt:check`, ті самі кроки, що в `quality.yml`, близько 26 s на пуш.
3. `CLAUDE.md` репо: розділ про хуки. Не обходити `--no-verify`; якщо хук упав, виправити причину; що запускає кожен хук.
4. CI не змінюється: `quality.yml` уже ставить `HUSKY: 0` для `npm ci`.

## Готово, коли
Коміт файлу з помилкою eslint зупиняється на `pre-commit`; пуш з помилкою `tsc` або новим `.catch(() => {})` зупиняється на `pre-push`; чистий коміт і пуш проходять; правило в `CLAUDE.md`.

## Ризики
Для команди: після `npm install` хуки спрацюють у всіх, тож перед мержем попередити (Yevhen). `pre-push` близько 26 s на кожен пуш; якщо заважатиме, `tsc` і повний lint лишаються лише в CI, а в `pre-push` тільки `debt:check`. Коміт, що лише видаляє файли, `lint-staged` пропускає сам. `pre-push` перевіряє робоче дерево, а не лише коміти, що пушаться: незакомічені зміни можуть як зупинити чистий пуш, так і сховати помилку; пушити з чистим деревом або після `git stash`.
