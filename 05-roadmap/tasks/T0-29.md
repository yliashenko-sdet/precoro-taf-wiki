# T0-29. Вибір зачеплених тестів для локального прогону перед PR
Asana: — (завести після відкриття PR).
Біль: P19 (нова, проект у `pains.md`): перевірка PR у TAF локально — smoke замало, повний прогін перевантажує ноутбук.

## Контекст
Стеля локальної машини команди — 16 ядер, тобто 4 воркери; повний локальний прогін (smoke + Full run, 1 289 тестів на 15.10) іде понад 3,5 години і під навантаженням дає таймаути, яких нема на Jenkins. Smoke (309 тестів) не покриває змінений код. PR у TAF зазвичай чіпає кілька методів сторінок або спеків, тож потрібний набір — smoke плюс тести, що реально проходять через змінений код.

Заміри 16.10 (прототип у scratchpad сесії, `develop` після #283):
- Граф імпортів між файлами непридатний (так працює `playwright test --only-changed`): 228 із 303 не-спекових файлів транзитивно доходять до понад половини з 89 спеків, бо фікстури імпортують майже всі сторінки.
- Граф викликів через TypeScript `findReferences` (від методу вгору до `test(...)`) працює і швидкий: `fillPostPaymentPercent` 2 тести, `openPaymentDialog` 22, `safeClick` 189 + 29 фікстур, `waitForLoaderToDisappear` 900 + 108 фікстур; 0,2–2,2 с на метод.
- `describe.serial` у тестах нема, динамічних викликів `this[name]` нема — статичний аналіз бачить усі виклики.

## Підхід
1. Скрипт `scripts/affected-tests.js` (детермінований, без Claude):
   - `git diff <base>...HEAD` + незакомічене → змінені рядки → оголошення, що їх містять (метод, функція, властивість/локатор, фікстура, тест);
   - від кожного оголошення `findReferences` вгору до `test(...)`; фікстура → тести, які беруть її в аргументах, і фікстури, що від неї залежать;
   - змінений тест входить сам; новий спек — усі його тести;
   - тест → `QaseID` з анотації;
   - глобальні файли (`playwright.config.ts`, `global-setup`, `timeouts.ts`, `run_env.ts`, `package.json`, плагін Babel тощо) і понад поріг тестів → вердикт «повний прогін»; змінені не-TS файли (`test_data`, снапшоти) шукаються за ім'ям у коді;
   - вивід: список тестів з причиною (який змінений символ), файл ID і готова команда; `--json` для скіла.
2. Запуск без нового фільтра: smoke-ID із сервісу ∪ зачеплені ID у файл, `QASE_SCOPE_IDS_FILE` (`docs/qase-scope.md`) через `scripts/run-local.sh` / `start.sh` скіла `local-run`.
3. Скіл `.claude/skills/affected-tests/SKILL.md`: запускає скрипт, пояснює вибір, показує команду для редагування, передає старт у `local-run`.
4. Розділ у `docs/local-run.md`: як вибрати набір перед PR.

## Готово, коли
- Скрипт на кількох реальних змінах дає список, який збігається з ручною перевіркою (по одному прикладу на тип: зміна в спеку, метод сторінки, фікстура, базовий метод, глобальний файл).
- Перевірка на історії: скрипт прогнано по останніх змерджених PR у `develop`, розподіл «скільки тестів вибрано» в цій картці.
- Статичні перевірки зелені; прогін тестів не потрібен (тести не змінюються).

## Ризики
- Тести, що мовчки залежать від побічних ефектів попередніх тестів на спільних даних компанії, на вибірці можуть падати не через PR. Кожен такий випадок — знахідка в `findings.md`.
- Вибірка не замінює нічний прогін: вона дає підставу відкрити PR, повний прогін лишається на Jenkins.

## Відкинуто
- `playwright test --only-changed`: файловий граф, вибирає майже все (заміри вище).
- Скіл без скрипта (Claude сам вирішує, що зачеплено): недетерміновано, не пояснити команді, не винести в CI.

## Результат
PR #297 у `develop` (коміт `34e6e749`), гілка `feature/liashenko/T0-29-affected-tests` від `develop` `82882a76`: `scripts/affected-tests.js`, скіл `.claude/skills/affected-tests/`, розділ «Що прогнати перед PR» у `docs/local-run.md`, `npm run test:affected`, `affected-ids.json` у `.gitignore`.

Перевірка на п'яти типах змін (16.10, тимчасові правки; числа — зачеплені тести без smoke, який іде в набір завжди): метод сторінки `fillPostPaymentPercent` 3 тести, `openPaymentDialog` 25, тест у спеку 1, фікстура `createPoWithApproval` 10 (разом із трьома фікстурами, що від неї залежать; звірено вручну по спеках у `tests/documents/`), базовий `safeClick` 122, `timeouts.ts` → повний прогін. Також: локатор `to_pay_input` 25, локатор із `BaseDocumentLocators` через spread 5, `Constants.control_account_payments_list` 1, файл даних `Attachment.pdf` 67. Наскрізно: зміна в `openPaymentDialog` → 157 кейсів (smoke 143 + 14), `--list` з цим файлом дає 324 тести (smoke сам 309).

Перевірка на історії: 32 останні мерджі в `develop` (#183…#283), скрипт на кожному merge-коміті проти першого батька, smoke і скоуп із сервісу 16.10 (843 кейси):
- вибірка — 14 PR: 143–287 кейсів, 17–34% повного (6 PR без зміни коду в `src/` — лише smoke);
- повний прогін через глобальний файл — 9 PR: `playwright.config.ts` 7, залежності в `package.json` 1 (#269), `scripts/run-local.sh` 1 (#283);
- повний прогін через частку ≥ 40% — 9 PR: codemod-и й зміни базових методів (`waitForLoaderToDisappear`, `click`, `doLogin`, `clickCl…` у міксині кнопок), 58–97%.

Що виправлено за ходом перевірки на історії: перевизначені методи (`findReferences` зводить override з базовим методом: `StockTransferPage.acceptItemEditing` давав 280 тестів, став 1); рядки типів у `extend<{...}>()`; auto-фікстура рівня воркера (`companyProfileSetup`) вимагає один тест на компанію, а не всі тести; видалення цілих елементів нічого не вибирає (їхні користувачі змінені, інакше не пройде typecheck); зміна лише npm-скриптів у `package.json` не глобальна; кейси поза скоупом Qase не беруться (`--all`, щоб узяти): у коді 1 790 кейсів, у скоупі 843.

Статичні перевірки: `typecheck`, `lint` (0 помилок, 16 попереджень — ті самі, що в `develop`, код у `src/` не змінювався), `debt:check`, `qase:check` зелені. Прогону тестів не було: тести не змінювались.

Відкрито: зміна в `playwright.config.ts` завжди дає повний прогін, хоча частіше за все це список проектів (#270 порядок, #268, #229 новий проект); звузити — окремим кроком, коли буде потреба. Виклик через змінну базового типу, який під час виконання потрапляє в перевизначений метод, не видно (описано в скілі).
