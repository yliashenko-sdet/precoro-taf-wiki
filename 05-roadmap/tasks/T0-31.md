## Контекст
ADR-012 (Draft): гілка `taf-stats` у репо TAF, один файл на запуск, `schema/v1.json`, єдина точка запису. Джерела: нічний QA Jenkins (Allure), гілкові прогони GHA продукту (лог Playwright), новий екшн «фіксова гілка → develop». Прототип парсера логу GHA перевірено на 92 логах (ADR-012, «Контекст»). `team_stats.py` вже має парсер Allure, класи симптомів (`failure_class`), збір PR і боргу.

## Підхід
1. Схема v1 (`schema/v1.json`) і гілка `taf-stats` (orphan) із порожнім `data/`. Формат узгоджений з виходом екшну фіксових гілок.
2. `scripts/stats/write-run`: валідація, checkout `taf-stats`, коміт, `pull --rebase`, `push` із повтором, `concurrency`.
3. Парсер Allure (нічний) і парсер логу Playwright (гілкові) у `scripts/stats/`, один формат запису.
4. Workflow `stats-collect.yml` (cron, береться з `develop`): нічний із Jenkins, гілкові з GHA продукту (токен лише на читання), лише нові запуски.
5. Перенесення наявних даних із `~/Work/Precoro/stats/raw` у `data/`.
6. Тижневий звіт і `data.json` сторінки читають `taf-stats`; `team_stats.py` і launchd вимикаються після збігу показників за тиждень.

## Готово, коли
- Запис за схемою від трьох джерел лежить у `taf-stats`; невалідний запис відхиляється з поясненням.
- Збір працює без ноутбука щонайменше тиждень; показники тижня збігаються з `team_stats.py` за ті самі дні.
- Гілкові показники (`branch.*`), сліпі з 21.10, знову рахуються.
- `taf-stats` виключена з правил захисту гілок (адмін репо); секрети лише в GitHub Secrets.

## Ризики і залежності
- Права запису і токен читання Actions продукту: адмін репозиторіїв.
- Досяжність QA Jenkins із раннера GitHub (питання до Максима); запасний варіант — push із самого нічного.
- Переписування збирача з Python на Node; показники мають збігтись.
