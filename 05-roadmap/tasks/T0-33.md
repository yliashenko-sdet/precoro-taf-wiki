# T0-33. Гейт smoke як commit status: зелений smoke тримається до нового коміту, лейбл `adaptation`
Біль: мерж блокується незалежно від якості коду. Статус: in progress (2026-11-16).

## Біль
Після вмикання ruleset репо (13.11, required check `E2E smoke`) PR блокувались на незміненому коді із зеленим smoke: #467, #468 (16.11). Причина: merge box бере лише останній запуск workflow на кожну подію. Апрув людини після апруву CodeRabbit — подія `pull_request_review`, вона створює запуск `full-run`, який Gate пропускає, без job-а `E2E smoke`; чек стає «Expected». Мержились лише PR, де людина апрувнула до CodeRabbit (#457) або лейбл `e2e full run` перезапустив smoke на апрув людини (#451).

Другий випадок (Олександр, Slack 16.11): тести, адаптовані під зміну продукту, якої ще нема в `develop`, на smoke проти `develop` червоні за задумом, і PR не змерджити.

## Підхід
- Рішення Євгена 16.11: ruleset умов не має (лише назви чеків), тому логіка у workflow. `full-run.yml` не змінюється (лише коментарі), новий `.github/workflows/smoke-status.yml` ставить commit status `E2E smoke passed` за останнім завершеним job-ом `E2E smoke` коміту і лейблом `adaptation`: зелений → success; червоний з лейблом → success з поміткою; червоний без → failure; нема завершеного → нема статусу («Expected»). Скасований чи пропущений smoke нічого не змінює.
- Тригери: `workflow_run` (завершення `full-run`), `labeled`/`unlabeled` лейбла `adaptation`, ручний з номером PR.
- Статус з іншою назвою, ніж job: `workflow_run` береться з `develop`, тож до мержу статусу нема; PR мерджиться під старим чеком, після мержу ruleset міняється на `E2E smoke passed`.
- Як у продукті (`precoro/precoro` `pr-checks-on-review.yml`, перезапуск рану на апрув CodeRabbit) не робили: захищає лише від ревʼю, не від лейблів.

## Готово, коли
- `smoke-status.yml` у `develop`, ruleset репо вимагає `E2E smoke passed` замість `E2E smoke`, лейбл `adaptation` створено.
- Перевірено на живому PR: апрув CodeRabbit → smoke → статус success → апрув людини → мерж не заблоковано.
- Документи: `docs/gha-full-run.md`, `docs/pull-request-guide.md` (правило `adaptation`: PR продукту і список очікуваних падінь в описі), `CLAUDE.md`.
