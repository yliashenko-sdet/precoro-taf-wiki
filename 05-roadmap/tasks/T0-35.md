# T0-35. Self-review перед кожним PR обов'язковий

Біль P20 (зміни довго доходять до `develop` через чергу рев'ю): рев'ю людей і CodeRabbit не мають ловити те, що локальне рев'ю знайшло б до PR. Етап 2. Додано 2026-11-16 (рішення Євгена). У запиті скіл названо `taf-pr-create`; у репо він називається `taf-pr-open`.

## Як зараз

- `taf-pr-open`, крок 4 «Локальне рев'ю», уже викликає `taf-pr-review`.
- Крок можна пропустити. `taf-pr-review` бере гілку з GitHub, тому гілку треба спершу запушити; без «так» на push рев'ю не робиться, і в описі пишеться причина.
- `docs/pull-request-guide.md` (розділ 1, «Локальне рев'ю», і `## Before PR check`) допускає «Локальне рев'ю не робилось: <чому>».

## Що зробити

1. `taf-pr-review` уміє рев'ю локальної гілки проти `origin/develop` без push і без номера PR.
2. `taf-pr-open` не створює PR і не переводить Draft у Ready, поки `taf-pr-review` не пройшов по останньому коміту. Після виправлень рев'ю повторюється, як зараз повторюються статика і прогін.
3. З гайду PR прибрати варіант «не робилось»; лишається «що знайшло і що з цим зроблено».

## Готово, коли

PR, відкритий через `taf-pr-open`, завжди має в `## Before PR check` результат локального рев'ю по останньому коміту; знахідки виправлені або пояснені в описі.
