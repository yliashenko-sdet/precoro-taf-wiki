# T1-25. Генерація типів і схем з OpenAPI, фасад над клієнтом
Перший крок API-блоку. Етап 1: перевіряється компілятором, середовища не потребує. ADR-005.

## Контекст
Специфікація виміряна 2026-09-22 (`01-context/archive/precoro-openapi-2026-09-22.json`): OpenAPI 3.0.0, 521 операція, `operationId` скрізь, 63% зі схемою відповіді, 115 схем у `components`, 61 із `required`. Клієнт TAF будує 172 унікальні шляхи: 121 є у специфікації, 104 мають схему відповіді, 51 поза специфікацією (внутрішній API з фронту; інфра-AQA каже, що покриття для них має з'явитись).

Сьогодні: 7 типів на 241 метод, `Record<string, unknown>` близько 700 разів, 60 рукописних схем і валідатор на 25 рядків, що дивиться лише корінь.

## Підхід
1. `npm run api:generate`: `openapi-typescript` з `/api/docs` → типи; з тієї ж специфікації витягти JSON-схеми відповідей для рантайм-валідації (`components/schemas` плюс розкриті `$ref`). Результат комітиться.
2. `precoro_service.ts` лишається **тонким фасадом**: імена методів ті самі, типи параметрів і відповідей беруться зі згенерованих. 101 місце виклику в тестах не змінюється.
3. Явний поділ на `publicApi` (121 шлях зі специфікації) і `internalApi` (51 шлях поза нею) з коментарем про різну стабільність.
4. Артефакт для розробки готовий: `01-context/openapi-gaps-2026-09-22.md`. Група A: 34 операції на 17 шляхах, які TAF викликає, мають лише `default` у `responses`, тобто ні коду, ні тіла; половина це DELETE, де достатньо оголосити `204 No Content`. Група B: 45 шляхів поза специфікацією (внутрішній API). Група C: 6 динамічних шаблонів клієнта, які питати не треба.
5. Свіжість специфікації: `api:generate` у CI порівнює згенероване з комітнутим і червоніє при розбіжності (повний contract-check це T3-07).

## Готово, коли
`tsc` зелений на згенерованих типах; `Record<string, unknown>` у `src/api` помітно менше; схеми відповідей доступні в рантаймі; список 17 шляхів переданий розробці.

## Показник
Ендпоінтів TAF із доступною схемою для валідації: 0 → 104 (ціль 172 після покриття внутрішніх шляхів і 17 схем).
