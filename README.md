# Precoro TAF 2.0 README

Єдине місце, де зафіксовано, **що** ми змінюємо в тестовому фреймворку Precoro, **чому** і **як саме**. Вікі одночасно є контекстом для Claude Code і документом для команди.

Репозиторій TAF: `precoro-e2e-playwright` (TypeScript + Playwright, переклад із Python + Selenium у березні 2026).

## Почни звідси

`00-map.md`: уся історія на одній сторінці, три числа, з чого починаємо, що просимо. Хребет вікі це три файли: `01-context/pains.md` → `05-roadmap/pain-to-plan.md` → `05-roadmap/plan-to-tasks.md` з картками в `tasks/`. Усе інше довідка, яку відкривають за потреби.

## Як користуватись

- **Початок сесії**: `00-status.md` каже, де ми і що далі; `06-playbooks/working-agreement.md` каже, як працювати в репозиторії і де зупинятись.
- **Перед будь-якою роботою над TAF** прочитай `02-principles/principles.md`. Це п'ять хвилин, і це те, що відрізняє "правильно" від "як було".
- **Перед зміною конкретного шару** відкрий відповідний файл у `04-target/`. Там цільова форма і межа "що не чіпаємо".
- **Будь-яке нове рішення** це новий ADR у `03-decisions/` за шаблоном. Без ADR рішення не існує.
- **Кожна задача в трекер** береться з `05-roadmap/plan-to-tasks.md` і має критерій готовності та контрольний показник.

## Підключення до Claude Code

Точка входу для Claude: `CLAUDE.md` (порядок читання, правила, стартовий промпт). Профіль ліда, особистий контекст, передача контексту і контрольні питання: `08-agent/`, лише локально (у `.gitignore`).

Робочі сесії: розширення Claude для VS Code на корпоративному акаунті з окремим каталогом конфігурації `~/.claude-precoro` (задано через `claudeCode.environmentVariables`), у VS Code відкрита лише тека репо TAF; деталі в `CLAUDE.md`, розділ "Запуск". Сесії не запускати з теки вікі: пам'ять Claude прив'язана до теки старту, і друга точка старту вже раз дала застарілу копію пам'яті.

Після переїзду в репозиторій:

Скопіювати теку в репозиторій як `docs/taf-2.0/` і додати в `CLAUDE.md` репозиторію:

```
## TAF 2.0
Перед роботою над кодом прочитай docs/taf-2.0/README.md і дотримуйся docs/taf-2.0/02-principles/.
Рішення фіксуються в docs/taf-2.0/03-decisions/ як ADR. Не пропонуй патерни, заборонені в 02-principles/conventions.md.
Статус роботи над модифікацією фіксується в docs/taf-2.0/00-status
```

## Правила вікі

- Один факт живе в одному місці, решта посилається: цифри в `01-context`, правила в `02-principles`, "чому" в `03-decisions`, "як виглядає" в `04-target`, план і показники в `05-roadmap`, інструкції в `06-playbooks`.
- Нова біль з'являється в `01-context/pains.md`, і лише звідти народжується задача в `05-roadmap/plan-to-tasks.md`; `pain-to-plan.md` це представлення плану для керівництва.
- Стиль: короткі речення, своїми словами, без води.
- Кінець сесії: `00-status.md`, рядок у `99-log.md`, `07-open-questions.md`, якщо щось закрилось або відкрилось.
